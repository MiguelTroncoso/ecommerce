Paso 1. El modelo: un dato con validacion obligatoria

El atributo identificador del cliente tiene property y validacion en el setter. Si el RUT no cumple el Modulo 11 o el correo esta mal escrito, el objeto ni siquiera se construye. 

{% raw %}@identificador.setter
def identificador(self, valor: str) -> None:
    valor = str(valor).strip()
    if self._tipo_identificador == "EMAIL":
        if not validar_email(valor):
            raise IdentificadorInvalidoError(
                f"El correo '{valor}' no tiene un formato valido."
            )
    else:
        if not validar_rut(valor):
            raise IdentificadorInvalidoError(
                f"El RUT '{valor}' no supera la validacion Modulo 11."
            )
    self._identificador = valor{% endraw %}

Paso 2. Herencia y polimorfismo

Los tres subtipos heredan de Producto con super().__init__() y sobrescriben procesar_entrega(). El pedido recorre sus lineas sin preguntar de que tipo son: cada objeto sabe como se entrega.

def procesar_despacho_entregas(self) -> list:

Paso 5. Consumo de la API externa

{% raw %}def obtener_valor_dolar(self) -> ValorDolar:
    try:
        respuesta = requests.get(self._url, timeout=self._timeout)
        respuesta.raise_for_status()
        serie = respuesta.json().get("serie") or []
        ultimo = serie[0]
        return ValorDolar(float(ultimo["valor"]), str(ultimo["fecha"])[:10],
                          "mindicador.cl (API en linea)")
    except (requests.RequestException, ValueError, KeyError) as error:
        raise IndicadorNoDisponibleError(
            f"No fue posible obtener el dolar: {error}"
