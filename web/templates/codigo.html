Paso 0b. Los codigos los genera el sistema

El usuario nunca escribe el identificador de un cliente ni de un producto. Al registrar, el sistema calcula el siguiente codigo disponible consultando la base de datos y lo informa en el resumen: C01, C02, ... para clientes y F01, D01, S01, E01 para los cuatro tipos de producto. Los pedidos usan PED-1001.

Paso 1. El modelo: un dato con validacion obligatoria

El atributo identificador del cliente tiene property y validacion en el setter. Si el RUT no cumple el Modulo 11 o el correo esta mal escrito, el objeto ni siquiera se construye.

Paso 5. Consumo de la API externa

El precio no depende de un solo sitio: se recorre una cadena de proveedores con el mismo formato de respuesta y se usa el primero que conteste. Si fallan los dos, queda el ultimo valor guardado. 

{% raw %}def obtener_valor_dolar(self) -> ValorDolar:
    for nombre, base in self._proveedores:      # mindicador.cl y findic.cl
        try:
            return self._consultar_proveedor(nombre, base)
        except IndicadorNoDisponibleError as error:
            self.ultimos_errores.append(f"{nombre}: {error}")
    raise IndicadorNoDisponibleError("Ningun proveedor respondio.")

def _consultar_proveedor(self, nombre: str, base: str) -> ValorDolar:
    url = f"{base.rstrip('/')}/dolar"
    respuesta = requests.get(url, timeout=self._timeout)
    respuesta.raise_for_status()
    ultimo = (respuesta.json().get("serie") or [])[0]
    return ValorDolar(float(ultimo["valor"]), str(ultimo["fecha"])[:10],
                      f"{nombre} (API en linea)", nombre){% endraw %}
